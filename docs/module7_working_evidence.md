# Module 7 — bằng chứng và việc chưa đóng

Trạng thái: **đang chuyển, chưa nghiệm thu**.

Cập nhật: HTTP lịch sử thanh toán đã được kiểm thử với reader Infrastructure thật và LocalDB schema tối thiểu, có trường hợp khách và nhân viên trùng ID. Fixture thay đăng ký reader/context để trỏ vào database thử; đây không phải kiểm chứng DI production hoặc schema triển khai.

| Lát cắt | Ánh xạ và bằng chứng | Việc còn mở |
|---|---|---|
| Tính trạng thái thanh toán hóa đơn/lệnh | [CODE] `PaymentConfirmationService.ResolveDocumentPaymentStatus` chuyển sang `MyGarage.Domain.Payments.DocumentPaymentStatusRules.Resolve`; cùng hai caller cập nhật hóa đơn và lệnh. Không thay route hoặc schema. [TEST] Test các ngưỡng chưa trả/một phần/đủ/vượt và tổng bằng không; test luồng xác nhận đơn bán lẻ hiện có. | [OPEN] Đây chỉ là quy tắc thuần; `PaymentConfirmationService`, EF, giao dịch, webhook và gửi email vẫn thuộc ứng dụng cũ. Chưa chuyển toàn bộ use case sang Application/Infrastructure, chưa nghiệm thu trạng thái, hoàn tiền hoặc retry. |
| GET `/api/payments/mine` — `payosApi.js` | [CODE] Controller chỉ cho role Customer, xác định actor và ghi header; Application gọi cổng đọc được triển khai bởi `Infrastructure/Payments/CustomerPaymentsReader` qua context đọc bảng hiện có, không dùng migration. Lịch sử PayOS lấy từng trang server. [TEST] HTTP InMemory kiểm tra phạm vi/shape; LocalDB so sánh adapter mới và cũ. | [OPEN] HTTP fixture dùng adapter cũ, chưa chứng minh toàn bộ pipeline runtime với context mới; SQL test dùng schema đã điều chỉnh. Context đọc dùng kết nối riêng và không dùng cho transaction ghi. Frontend chưa kiểm thử tương tác trình duyệt; endpoint vẫn là REST. |
| Truy vấn hóa đơn | [CODE] `/odata/Invoices` qua `Application/Payments/InvoiceQuery` và `IInvoiceQueryReader`; scope chi nhánh/khách được xác định ở controller trước khi áp dụng OData, adapter EF tạm thời trong Web. [TEST] HTTP InMemory kiểm tra scope và `$select`, `$orderby`, `$top`; SQL kiểm tra lọc và phân trang trên schema thử điều chỉnh. | [OPEN] `/api/invoices` legacy có quyền khác; chưa chuyển caller kế toán. Màn hình kế toán còn cần trường và tổng hợp toàn bộ theo bộ lọc; không tính tổng theo trang hiện tại. Kiểm kê filter/count/export và schema nguyên trạng. |
| Tổng thuế hóa đơn — `TaxDocumentsPage` | [CODE] `GET /api/invoices/tax-summary` tổng hợp tổng thuế, số hóa đơn thuế khác 0 và 30 dòng gần nhất trên server; client không tải toàn bộ hóa đơn để tính. Đường đọc đi qua cổng Application, adapter EF tạm Web. [TEST] HTTP và LocalDB với dữ liệu null, âm, 0 và >30; frontend kiểm tra dữ liệu trả về, build/encoding. | [OPEN] Giữ quyền mọi Staff xem toàn bộ như API legacy, chưa đạt scope chi nhánh của OData. Truy vấn tổng/đếm và danh sách không đọc cùng snapshot và có thể lệch khi ghi đồng thời. SQL dùng schema đã điều chỉnh; chưa thử UI trên browser hoặc benchmark. |
| Danh sách/chi tiết hóa đơn — `InvoicesPage` | [CODE] `GET /api/invoices/list-page` lọc, tổng hợp và phân trang; `GET /api/invoices/{id}/view-detail` chỉ tải chi tiết và thanh toán của hóa đơn chọn, mỗi danh sách có trang riêng. Frontend dùng hai endpoint, chặn phản hồi cũ và giới hạn trang. [TEST] HTTP kiểm tra quyền legacy, DTO và bộ lọc; LocalDB kiểm tra search có dấu và truy vấn chi tiết trên schema thử. | [OPEN] Các adapter vẫn trong Web; chưa thử tương tác browser, benchmark, schema nguyên trạng hay mọi biên collation. Scope mọi Staff toàn chi nhánh kế thừa API cũ; tổng và danh sách không chung snapshot. |
| Xác nhận thanh toán → tồn | [CODE] `PaymentConfirmationService` lưu trạng thái và cập nhật chứng từ trước khi gọi trừ kho; webhook cũng gọi đường trừ kho. | [OPEN] Chưa xác nhận tính nguyên tử, mất ACK, webhook lặp/sai thứ tự, gửi email hoặc khả năng replay; không coi việc tách quy tắc trạng thái là nghiệm thu luồng này. |

Không chạy migration hay thay đổi schema trong lát cắt này. Phục hồi bằng cách hoàn nguyên thay đổi mã liên quan sau khi kiểm tra caller; không khẳng định an toàn production chỉ từ kiểm thử cục bộ.
